## Task 12.3: Write property test for the candidate cap
Property 13: Candidate count and cap. Requirements: 9.2, 9.3, 12.4, 13.3
### Changes
- `tests/properties/test_prop_candidate_cap.py` (new), tagged `# Feature: tape-rescue, Property 13: Candidate count and cap`. Settings: `max_examples=200`, `derandomize=True`, `deadline=None`.
  - Generator `cases()`: 2–3 reads with distinct random 64-hex capture IDs, payload length 1–48, 0–8 differing offsets. At each differing offset it picks `k` distinct values (2 ≤ k ≤ number of reads) and spreads them over the reads so all `k` occur, so the expected candidate count (product of `k`) is known by construction. The recorded CRC is either the CRC of a randomly assembled candidate (a match exists) or a random 16-bit value. The cap is drawn from 64, the exact count, count − 1, or 0–256.
  - `test_candidate_count_and_cap` (direct `reconstruct` call, `(capture_id, payload)` pairs): `candidate_count` and `outcome.candidate_count` equal the constructed product. Above the cap: `cap_exceeded`, `evaluated_count == 0`, `match_count is None`, no payload, no chosen bytes, and the wrapped `taperescue.engine.reconstruct.crc16_xmodem` is called 0 times. At or below the cap: `evaluated_count == count` and the CRC is called exactly `count` times (the search is never cut short); `match_count >= 1` when the CRC came from a candidate; a payload is returned if and only if `match_count == 1`; reason is `no_match` / `None` / `multiple_matches` accordingly.
  - `test_cap_exceeded_through_recover`: the same cases as a three-block session (block 0 anchor, block 1 under test, block 2 final) through `recover(..., RecoverOptions(candidate_cap=cap))`. A read's data CRC outcome is `valid` only when its payload matches the recorded CRC; in that case step e decides first and the test only checks the block is `Intact` or `Conflict`. Otherwise above the cap the block is `Unresolved`, `cap_exceeded`, never `Reconstructed · CRC match`, no payload, no supporting IDs, 0 evaluated, 0 CRC calls; within the cap every candidate is evaluated and `Reconstructed · CRC match` occurs only with `match_count == 1`.
  - The CRC is wrapped with `unittest.mock.patch.object(..., wraps=...)` inside the test body (the real function still runs), which avoids Hypothesis's function-scoped-fixture health check on `monkeypatch`.
- No production code changed. The property found no bug.
