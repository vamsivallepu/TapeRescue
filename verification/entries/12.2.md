## Task 12.2: Wire reconstruction into `recover`
Requirements: 9.1, 9.8, 9.9, 9.10, 9.12, 14.2
### Changes
- `taperescue/engine/__init__.py`: added decision steps g to l and appended them to `DECISION_STEPS` after `step_f_single_capture`, in the design's order. Only valid-header reads supply bytes or CRCs.
  - g `step_g_intact_only`: `options.reconstruct` false gives `CRC failed`, reason `None`, `reconstruction = None` (the report renders this as `attempted: false`).
  - h `step_h_single_read`: fewer than two valid-header reads gives `Unresolved`, `single_read`.
  - i `step_i_truncated`: any valid-header read with `payload_state == "truncated"` or a payload length different from the header's `block_len` gives `Unresolved`, `truncated_payload`.
  - j `step_j_crc_unreadable`: any valid-header read with an unreadable (or absent) data CRC gives `Unresolved`, `crc_unreadable`.
  - k `step_k_crc_mismatch`: differing recorded data CRCs give `Unresolved`, `crc_mismatch_between_reads`.
  - l `step_l_reconstruct`: calls `reconstruct([(capture_id, payload), ...], recorded_crc, options.candidate_cap)`. One match gives `Reconstructed · CRC match` with the payload, the outcome (choices with chosen values and supporting IDs), and `supporting_capture_ids` = sorted IDs of the captures whose reads entered the search. `no_match`, `multiple_matches`, `cap_exceeded` give `Unresolved` with that reason, `payload = None`, no supporting IDs, and the outcome attached (candidate, evaluated and match counts).
  - Steps h to k leave `reconstruction = None`. No step computes or stores a substitute CRC; the recorded CRC is only compared against.
  - The submodule is imported as `from taperescue.engine import reconstruct as _reconstruct`. Importing the function name directly shadowed the `taperescue.engine.reconstruct` module attribute and broke `tests/engine/test_reconstruct.py::test_cap_exceeded_evaluates_nothing` (found on the first full run, fixed).
- `taperescue/engine/selection.py`: docstrings only (where steps g to l live; `undecided` is now a safety net, since step l always decides).
- `tests/engine/test_selection.py`: `test_multi_capture_failure_is_never_recovered` asserted the pre-12.2 placeholder (`CRC failed`). Identical reads with a non-matching recorded CRC now give `Unresolved`, `no_match`; the test asserts that and still asserts no payload.
- `tests/test_uef_exporter.py` (edited with orchestrator authorisation, one test only): `test_reconstructed_block_uses_recorded_crc` asserted `base.blocks[1].payload is None` (true only before `recover` could reconstruct) and then built the reconstructed block by hand with `dataclasses.replace`. See Resolution below. The now-unused `import dataclasses` was removed.
- `tests/engine/test_recover_reconstruct.py` (new, 12 tests): byte-array sessions (block 0 anchor, block 1 under test, block 2 final) for steps g, h, i, j, k, l; the brief's unique repair, same-error, collision and cap cases through `recover`; `candidate_cap` taken from `RecoverOptions`; precedence i before j, j before k, c before l, g before i; export gate outcome for each; and the end-to-end damaged-fixture run (skipped when `build/decoder/ScanTape` is missing).

### Resolution of the stale exporter test
- Previous blocker: `tests/test_uef_exporter.py::test_reconstructed_block_uses_recorded_crc` asserted that `recover` left block 1 unresolved (`payload is None`) and then hand-built a `Reconstructed · CRC match` block. With 12.2 the engine reconstructs that block itself, so the assertion failed.
- Change (that test only; no production code changed, no other assertion touched):
  - Removed `assert base.blocks[1].payload is None` and the two `dataclasses.replace` calls that built `rebuilt` and `result`.
  - Added `assert base.blocks[1].status == "Reconstructed · CRC match"` and `assert base.blocks[1].payload == tb.payload`.
  - `export_decision` and `export_uef` now take `base` directly. The kept assertions are `decision.permitted and decision.reconstructed_blocks == (1,)` and `assert_matches_capture(out, blocks, PROGRAM)`. The second checks that the file's data CRC for block 1 equals the originally recorded `tb.data_crc`, that the reader's CRC checks pass, and that the payloads join to the program. `export_uef` runs `verify_export` before returning, so a successful return means verification passed.
  - Removed `import dataclasses`, which nothing else in the file used.
