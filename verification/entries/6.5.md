## Task 6.5: FSK modulator
Requirements: 4.7, 4.8, 4.9
### Changes
- `taperescue/fixtures/fsk.py` (new):
  - Segments: `Carrier(cycles)` is continuous 2400 Hz. The count must be even because a `1` bit cell holds two cycles. `Gap(cells)` is silence measured in bit cells. `ByteFrames(values)` takes ints or `block_builder.ByteFrame` objects and writes each byte as a start bit `0`, eight data bits LSB first, and a stop bit `1`.
  - A `0` cell is one cycle of 1200 Hz and a `1` cell is two cycles of 2400 Hz. Cell `k`, counted from the start of the stream, covers samples `floor(k*147/4)` to `floor((k+1)*147/4)` (`bit_start_sample`), so every cell is 36 or 37 samples. The arithmetic is integer only.
  - `SINE_TABLE`: 256 int16 values at amplitude 16000, written out as a literal so the output does not depend on libm. Sample `i` of a cell with `n` samples and `c` cycles is `SINE_TABLE[(256*c*i)//n % 256]`. Each cell starts at phase 0, so tone changes happen at a zero crossing. The six possible cell waveforms are precomputed.
  - `wav_header`/`modulate`: a hand-written 44-byte RIFF header (PCM, 44100 Hz, 16-bit, mono, no other chunks), followed by little-endian samples.
  - `TapeTiming` and `BBC_TIMING`: the single table of lead-in constants, in integer cycles or cells. The comment table in the module cites the source for each value:

    | Field | Value | Source |
    | --- | --- | --- |
    | `leading_gap_bits` | 600 cells (0.5 s) | Room before the first tone |
    | `first_prelude_cycles` | 4 | AtomTapeUtils `bbmTiming` nominal prelude (minimum 3) |
    | `dummy_byte` | `0xAA` | BBC dummy byte between prelude and lead tone (`BlockDecoder.cpp` comment) |
    | `first_lead_cycles` | 12240 (5.1 s) | BBC: 5.1 s of 2400 Hz leader before a file ([DSP Stack Exchange](https://dsp.stackexchange.com/questions/72332/convert-old-computer-cassette-signal-into-binary)). Decoder minimum 2.0 s |
    | `other_lead_cycles` | 2160 (0.9 s) | BBC: 0.9 s between blocks recorded in one go (same source). Decoder minimum 0.2 s |
    | `trailer_cycles` | 4800 (2.0 s) | Design value. Decoder needs at least 0.5 s after the last block (nominal 5.3 s) |
    | `trailing_gap_bits` | 1200 cells (1.0 s) | Silence at the end |
  - `tape_stream(frame_lists, timing)` builds the segments for one file: leading gap, then prelude, dummy byte, and 5.1 s lead before block 0, and 0.9 s lead before every later block. The block frames follow each lead, and the file ends with the trailer and the trailing gap.
  - `segment_start_samples(stream)` returns the start sample of every segment plus the total sample count. Tests use it to compare against the decoder's `sample_offset`.
  - The module imports only `struct`, `dataclasses`, and `typing`. It imports nothing from `taperescue`, so nothing from `taperescue.decoder_adapter`, and it never runs the decoder.
- `tests/test_fsk.py` (new, 18 tests):
  - Bit boundaries equal `floor(k*147/4)` for k < 10000, and 1200 cells are exactly 44100 samples.
  - The sine table matches its definition.
  - `wavcheck.inspect_wav_header` reads the header as PCM 44100/16/1.
  - A `0` cell has one cycle, a `1` cell has two cycles, and every cell starts at 0.
  - Byte frame bit order is correct for `0b11001010`.
  - Carrier and gap lengths are correct.
  - `ByteFrames` accepts `block_builder` frames.
  - Odd or negative carriers, negative gaps, out-of-range bytes, and an empty block list are rejected.
  - Timing values are checked against the BBC and decoder minimums.
  - The `tape_stream` layout is checked.
  - Output is byte-identical across two runs.
  - An AST check confirms there are no `taperescue`, `subprocess`, or `os` imports and no `ScanTape` reference.
  - Integration test (skipped with a reason when `build/decoder/ScanTape` is missing): runs the real decoder on an 8-block program (see below).
### Real decoder check
Program: `random.Random(65).randbytes(1800)` (non-periodic, so every block has a different data CRC), built with `build_blocks` (8 blocks: 7 × 256 bytes and 1 × 8 bytes) and modulated with `tape_stream` + `modulate` using `BBC_TIMING`. The WAV is 2,814,506 bytes (31.91 s), SHA-256 `9f8b89e54f0edeefaf548288715dce9ec5d9e9d54feb5b7a1fb90dd77c4c98ef`.

The decoder therefore accepts a wide range around these values. The fixtures use the BBC values above.

### Notes
- Carrier lengths must be even cycle counts so every segment fills whole bit cells and boundaries stay on the global `floor(k*147/4)` grid.
- For the UEF exporter task, not changed here: the design gives the UEF `0x0110` carrier as "5100 cycles before block 0, 1800 before other blocks". If chunk `0x0110` counts cycles at twice the base frequency (2400 Hz), as the UEF format describes, then 5.1 s is 12240 cycles and 0.9 s is 2160 cycles, the same values as `BBC_TIMING`. This should be checked when the exporter is written.
- No property test was added. Property 6 (deterministic fixture generation) belongs to task 6.9. A plain determinism unit test is included.
