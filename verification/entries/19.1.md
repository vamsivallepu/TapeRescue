## Task 19.1: Implement `server/sessions.py`
Requirements: 3.3, 17.2, 17.3
Run from `/home/vamsik/TapeRescue` with Python 3.12.3 (`.venv`). Nothing was committed or pushed. Only `server/`, `tests/server/`, `pyproject.toml` and this entry were changed.
### Changes
- `pyproject.toml`:
  - New optional dependency group `server`: `fastapi>=0.110`, `uvicorn>=0.29`, `python-multipart>=0.0.9`, `httpx>=0.27` (`httpx` is for FastAPI's `TestClient`). The design keeps the server outside the `taperescue` wheel ("installs the `taperescue` wheel and server requirements, copies ..."), so these are optional, not main dependencies.
  - `[tool.pytest.ini_options]`: added `pythonpath = ["."]`, because `server/` is not in the installed package and `--import-mode=importlib` does not put the root on `sys.path`. Without it, `server.sessions` imports only under `python -m pytest`, not bare `pytest`.
- `server/__init__.py` (new): package marker.
- `server/sessions.py` (new):
  - `SessionStore(parent=None, *, clock=time.monotonic, idle_timeout_s=3600, max_upload_bytes=MAX_BYTES)`. The root is a fresh `tempfile.mkdtemp(prefix="taperescue-sessions-", dir=parent)` directory, chmod 0700 again in case of an unusual umask. `close()` removes it.
  - `create()` makes `<root>/<uuid4().hex>/` with mode 0700. `get(sid)` and `touch(sid)` update `last_access` from the injected clock. `delete(sid)` removes the directory at once and returns whether the session existed.
  - `sweep()` removes every session with no upload in progress whose idle time is `>= idle_timeout_s` (60 minutes), and returns the sorted IDs it removed. `run_sweeper(interval_s=60)` is a coroutine that runs `sweep` in a worker thread every interval until cancelled, for the FastAPI lifespan in task 19.3.
  - `save_upload_sync(sid, index, chunks, display_name)` and `async save_upload(...)`. The async form accepts an async or a plain iterable of `bytes`. `iter_upload(upload, chunk_size=1 MiB)` turns any object with `async read(n)`, such as `UploadFile`, into an async iterator. Uploads go to `capture_<index>.wav.part` (opened with `O_NOFOLLOW`, mode 0600), with a running byte count. When the count passes `max_upload_bytes` (64 MiB, `taperescue.wavcheck.MAX_BYTES`), the partial file is closed and deleted and `UploadTooLarge` is raised with code `too_large`, `capture_index`, and the message `Capture is larger than the 64 MiB limit (67108864 bytes)`. An upload of exactly the limit is kept. On success the `.part` file is renamed to `capture_0.wav` or `capture_1.wav`.
  - The user filename goes only into `StoredCapture.display_name`, with non-printable characters dropped and a 255-character cap. It is never joined into a path.
  - Session IDs are checked against `[0-9a-f]{32}` with `fullmatch` before any path join. The joined path must also be a direct child of the root, and `_remove_dir` checks the same before `rmtree`. Capture indexes must be the `int` 0 or 1 (`bool`, strings and floats are rejected).
  - The session table is guarded by a `threading.Lock`. A session with an upload in progress is never swept. If a session is deleted during an upload, the upload raises `SessionNotFound` and leaves no files.
  - Typed errors, all subclasses of `SessionError` with `code` and a user-facing `message`: `InvalidSessionId` (`invalid_session_id`), `SessionNotFound` (`not_found`), both with the message `Session not found or expired`; `InvalidCaptureIndex` (`invalid_capture_index`); `UploadTooLarge` (`too_large`).
- `tests/server/test_sessions.py` (new, 35 tests): private 0700 root (given parent and default temp dir, removed by `close`); generated 32-hex IDs and 0700 session directories; generated stored names with a hostile display name (`../../etc/passwd\x00evil.wav`) kept out of paths; sync, async, and async-with-plain-iterable uploads; invalid capture indexes; upload of exactly the limit kept; over-limit abort that stops reading at the crossing chunk and leaves the session directory empty (sync and async); default limit 64 MiB; `last_access` update on `get`; sweep with an injected clock that keeps a session at 59:59 idle, removes it at 60:00, and keeps a session touched 1 s earlier; sweep skipping an in-progress upload; `run_sweeper`; delete on request; upload to a deleted session; 14 invalid session IDs (traversal, wrong length, uppercase, `/`, newline, NUL, non-ASCII digits, `None`, `int`) rejected by `get`, `delete`, `capture_path` and `save_upload_sync` with no change to the root; unknown valid ID gives `SessionNotFound`; 8 threads creating, uploading and deleting 160 sessions.
