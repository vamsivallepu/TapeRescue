## Task 12.7: Property test for missing evidence (Property 17)
Requirements: 9.1, 9.8, 9.9, 9.10, 9.12, 12.5, 13.3
### Changes
- `tests/properties/test_prop_missing_evidence.py` (new). No engine code changed: no counterexample was found.
  - Tag: `# Feature: tape-rescue, Property 17: Missing evidence never produces a repair` (module docstring), plus the test docstring.
  - Settings: `max_examples=500`, `derandomize=True`, `deadline=None`. Strategies are local to the file.
  - Generator `scenarios()`: two captures with distinct random 64-hex IDs, 2 to 5 blocks, final block length 1 to 256, every block except the target intact in both captures (so the anchor check passes), random capture input order. The target block's deciding defect is drawn uniformly from the design's steps c, g, h, i, j, k. Extra defects come only from later steps, so the expected reason always follows step precedence:
    - `header_disagreement` (c): capture B's valid header differs in filename, load, exec, or a low flag bit. Bit 7 is never changed because it sets the final block. `block_len` is not varied, because a different declared length would also change `expected_len` and make the read truncated.
    - `intact_only` (g): `RecoverOptions(reconstruct=False)`.
    - `one_capture` (h): B either lacks the block or holds it only with an invalid header CRC. That invalid-header read carries the original payload and a valid data CRC, so it would allow a repair if it were used.
    - `truncated` (i): one or both valid reads are cut to an undamaged prefix of the original. The original often ends in zeros, and cuts are often placed inside that zero tail, so zero padding would rebuild the original exactly.
    - `crc_unreadable` (j): one or both valid reads have an unreadable data CRC.
    - `crc_mismatch` (k): one read records `crc(original) ^ delta`.
  - Without the defect the damaged reads would be repairable: the damaged offsets are disjoint and both reads record the original CRC.
  - Assertions on the target block: never `Reconstructed · CRC match`. `(status, reason)` matches the step table: `Conflict`/`header_disagreement`, `CRC failed`/`None`, or `Unresolved` with `single_read`, `truncated_payload`, `crc_unreadable`, or `crc_mismatch_between_reads`. `reconstruction is None`, so no candidate search ran and no choices or match count exist. `payload is None`, there are no supporting IDs, and `conflict.kind == "header"` appears only for header disagreement. The block's `reads` equal the generated observations exactly, so nothing was padded and no CRC was substituted. Every read satisfies `len(payload) == actual_len <= expected_len`. All other blocks are `Intact`, `program_payload()` is `None`, and `export_decision` is refused with `blockers == ((target, reason),)`, where the gate reason for intact-only mode is `crc_failed`. The target is not in `reconstructed_blocks`.
  - Example test `test_truncated_zero_suffix_is_not_padded`: a truncated read whose missing 56 bytes are zero in the original stays `Unresolved`/`truncated_payload`, and the gate blocks it. The control case gives the engine the same read already zero-padded, and the engine then reports `Reconstructed · CRC match` with the original payload. This shows that padding would be caught.
