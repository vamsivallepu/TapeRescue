## Task 8: Check decoder observations on the generated fixtures
Requirements: 2.1, 2.3, 2.4, 2.9, 3.5, 4.11, 5.6, 5.7
### Changes
- `tests/integration/test_fixture_decode.py` (new, 5 tests). Every test runs the real patched decoder through `taperescue.decoder_adapter.decode_capture`, which uses a real subprocess on real WAVs. Results are compared with `fixtures/starmap/reference_payloads.json` and `damage.json`. A module-level `skipif` skips the tests when `build/decoder/ScanTape` is missing or not executable, with the reason `patched decoder not built at <path>; run scripts/build_decoder.sh to enable the fixture decode integration tests`.
  - `test_clean_fixture_decodes_to_reference`: one observation for each of blocks 0–7. Every block is intact: header CRC valid, data CRC valid, and the recorded header CRC, data CRC, `header_raw`, filename, load and exec addresses, block length, flags, and payload all equal the reference. Only block 7 has flag bit 7. The concatenated length is 2025.
  - `test_damaged_fixture_block6_raw_observation[a|b]`: blocks 0–5 and 7 are intact and equal the reference. Block 6 has a valid header, `payload_state == "complete"`, 256/256 bytes, and data CRC `invalid` with `recorded` equal to the original CRC (reference and `damage.json`). The payload XOR the reference payload is exactly the `damage.json` `{offset: mask}` map for that side, and the observed values equal the `damaged` values.
  - `test_wav_cut_inside_block3_gives_truncated_observation`: the test builds `cut_block3.wav` in `tmp_path` from the 44-byte header and sample data of `clean.wav`, with the RIFF and `data` sizes rewritten by `fsk.wav_header`. The cut sample is block 3's clean `sample_offset` plus `ceil(((1 + 25 + 2 + 100) * 10 + 5) * 147 / 4)` samples. That is 100 whole payload bytes after the sync byte, the 25-byte `header_raw`, and the header CRC, plus 5 bits into payload byte 101. Assertions:
    - Blocks 0–3 are present and no block follows.
    - Blocks 0–2 are intact and equal the reference.
    - Block 3 has a valid header, `expected_len 256`, `actual_len 100`, and `payload_state "truncated"`.
    - Block 3's payload equals the first 100 reference bytes, with no padding.
    - Block 3's data CRC is `unreadable` with no recorded value.
  - `test_silent_wav_gives_no_blocks`: 1 s of zero samples (44.1 kHz, 16-bit, mono) raises `DecoderError` with code `no_blocks` and the message `No BBC 1200-baud blocks were found in this capture`.
- No change to the patch, the adapter, or any other file. The hook did not need to move to the byte reader (Requirement 2.9).

### Requirement 2.9
No observation field failed on the fixtures, so the patch was not changed. These failure modes are still not exercised by any WAV, as recorded in task 2.2:
- a header cut short (partial `header_raw`, `header_crc unreadable`)
- an unreadable header CRC
- a final block with a missing trailer tone
- noise or dropouts inside a payload, as opposed to a cut at the end of the file

The fixtures damage bits through clean FSK, so this task did not test resynchronisation on real noise.
