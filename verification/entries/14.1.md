## Task 14.1: Property test for the export gate (Property 21)
Requirements: 11.1, 11.2, 13.4
### Changes
- `tests/properties/test_prop_export_gate.py` (new). No engine or UEF code changed, because no counterexample was found.
  - Tag: `# Feature: tape-rescue, Property 21: Export gate` (module docstring), plus both test docstrings.
  - Settings: `max_examples=300`, `derandomize=True`, `deadline=None`. Strategies are local to the file. `tmp_path` is only a parent directory, and each example uses a fresh `TemporaryDirectory` inside it.
  - `test_export_gate_on_built_results` uses the `direct_cases()` generator, which builds `RecoveryResult` objects by hand.
    - Files have 1 to 6 blocks. The final block is 0 to 256 bytes and can be empty.
    - Flag modes are `normal`, `none` (no final flag) and `early` (the flag sits on block j < k-1 and later blocks of the same file are still in the captures).
    - Each required block gets a random status from Intact, Reconstructed, CRC failed, Unresolved, Conflict and Missing.
    - Non-recovered blocks get a random engine reason or `None`, and sometimes keep a payload. That checks the gate looks at status and not just at whether a payload exists.
    - Recovered blocks get at most one planted defect: filename, load or exec differs from the file's; header block number is wrong; stray final flag; final flag missing; 255-byte non-final block; 257-byte final block; payload length differs from the header; no payload; no valid-header read; a second valid header that disagrees; a duplicate `BlockResult`.
    - Header and data CRCs are real values from `crc16_xmodem`, so a permitted result can actually be exported.
    - The generator records the exact `(block, reason)` blockers each choice must cause. When every usable header has one identity, `set(blockers)` must equal that set exactly. When planted identities disagree, the gate's choice of which block to blame is a tie-break, so the test checks only that export is refused and that the planted blockers are a subset of the result.
  - `test_export_gate_on_recovered_captures` uses the `engine_cases()` generator, which feeds observations through `recover`.
    - Sessions have one or two captures. Each read is intact, damaged, truncated, has an unreadable CRC, has an invalid header (with a perfect payload), or is absent.
    - Some blocks get repairable damage: both captures damaged at different offsets, which yields `Reconstructed · CRC match` in about 14% of examples.
    - Sessions can include one renamed header and an early or missing final flag. With two captures, a forced anchor block avoids `PairingRejected`.
    - The expected outcome comes from the result itself. Export is permitted iff a final block is known, every required block is recovered, the chosen headers of recovered blocks share one (filename, load, exec), and no valid-header read of that file lies past the final block. In the last case `(final, "unexpected_final_flag")` must be listed.
  - Checks shared by both tests:
    - `permitted == not blockers`. Blockers are sorted with no repeats.
    - The decision is the same when computed twice, and the same when `blocks` and `captures` are reversed.
    - Every non-recovered required block appears as `(n, reason or fallback)` (Requirement 13.4). Every absent required block appears as `block_missing`.
    - With no final block, export is refused and the synthetic `(max+1, block_missing)` entry is listed (Requirement 11.2).
    - Blocker block numbers lie within the required range (plus the synthetic entry).
    - `reconstructed_blocks` lists exactly the single Reconstructed entries.
    - When export is refused, `export_uef` raises `ExportRefused` with the gate's blockers, and also raises when given a forged "permitted" decision. The output directory stays empty, with no temp files.
    - When export is permitted, `export_uef` writes `tape.uef` (its built-in independent-reader verification passes) and `read_uef` payloads concatenate to `program_payload()`.
