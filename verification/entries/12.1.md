## Task 12.1: Implement `taperescue/engine/reconstruct.py`
Requirements: 9.2, 9.3, 9.4, 9.5, 9.6, 9.7
### Changes
- `taperescue/engine/reconstruct.py` (new). Imports only `taperescue.crc.crc16_xmodem` and the `UnresolvedReason` alias from `taperescue.models`.
  - `OffsetChoice(offset, observed, chosen, supporting_capture_ids)`: `observed` is `(capture_id, value)` for every read, sorted by capture ID then value. `chosen` and `supporting_capture_ids` are filled only on a single match; otherwise `None` and `()`.
  - `ReconstructionOutcome(candidate_count, evaluated_count, match_count, payload, choices, reason)` plus a `reconstructed` property. `match_count` is `None` when the search was skipped above the cap.
  - `differing_offsets(reads)`: `(offset, distinct values sorted ascending)` for every offset where the reads disagree.
  - `candidate_count(reads)`: `math.prod` of the distinct-value counts, computed without building any candidate (1 when all reads agree).
  - `reconstruct(reads, recorded_crc, cap)`: above the cap returns `cap_exceeded` with `evaluated_count = 0` and no CRC call. Otherwise evaluates every candidate from `itertools.product` without stopping early. One match gives the payload with chosen values and the sorted IDs of every capture that observed each chosen value; zero gives `no_match`; more than one gives `multiple_matches` with the count. Reads are sorted by capture ID first, so input order does not change the outcome. Unequal lengths or an out-of-range CRC raise `ValueError`.
- Interface note: the design lists `reconstruct(reads: Sequence[bytes], ...)`, but `OffsetChoice` needs capture IDs, so `reconstruct` takes `(capture_id, payload)` pairs. `candidate_count` takes plain byte strings as designed. Task 12.2 will pass `(obs.capture_id, obs.payload)` for the eligible reads.
- `tests/engine/test_reconstruct.py` (new), 10 tests using `payload[i] = (17*i + 11*i*i + 42) % 256`.
