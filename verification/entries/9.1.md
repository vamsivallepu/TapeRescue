## Task 9.1: Implement the engine skeleton with intact selection
Requirements: 3.6, 8.1, 8.2, 8.3, 8.4, 9.11
### Changes
- `taperescue/engine/__init__.py`: `recover(captures, options=RecoverOptions())` as a pure function over `CaptureObservations`. `RecoverOptions` is imported from `taperescue.models` and re-exported, not redefined. Steps:
  - Normalise: group by `capture_id`, keep one copy per ID (the copy with the smallest canonical `repr`, so the choice never depends on input order), record each dropped copy in `duplicates_merged`, sort captures by ID and each capture's reads by `(block_no, sample_offset)`.
  - Place reads at block numbers. Valid-header reads use their parsed `block_no`. Invalid or unreadable-header reads supply no identity but are listed under a block for the report: the block number in their raw header bytes if it lies between the neighbouring valid block numbers in the same capture (inclusive), or at most one past the last valid block; otherwise the single gap between neighbours that are two apart; otherwise unplaced (kept in the capture, in no block).
  - Final block: lowest `block_no` among valid-header reads with flag bit 7. Required blocks `0..final`, or `0..max(placed block_no)` when no block is flagged (`final_block = None`; the gate in task 9.2 refuses export).
  - `DECISION_STEPS` tuple applied in order; first non-`None` result wins, else `selection.undecided`.
- `taperescue/engine/selection.py`: `BlockContext` (block number, reads sorted by `(capture_id, sample_offset)`, capture count, options; `valid_reads`, `intact_reads`), and steps:
  - a `step_a_missing`: no reads → `Missing`, `block_missing`.
  - b `step_b_header_invalid`: no valid-header read → `Unresolved`, `header_invalid`.
  - e `step_e_intact`: intact reads with one shared payload → `Intact`, payload (including `b""` for empty blocks), supporting IDs = every capture with an intact read, sorted. Declines when intact payloads differ (left to step d).
  - f `step_f_single_capture`: one capture and no intact read → `CRC failed`, `single_read`.
  - `undecided` fallback: `CRC failed`, reason `None`, no payload, no reconstruction (same shape as design step g).
- `tests/engine/test_selection.py`: 15 byte-array tests (no WAVs).

### Extension points and interim behaviour
- Task 11.1 inserts steps c (header disagreement) and d (payload conflict) between `step_b_header_invalid` and `step_e_intact` in `DECISION_STEPS`, and fills `anchors` (currently always `()`). Until then two captures with no anchor are not rejected, and intact reads with different payloads fall through to `undecided`.
- Task 12.2 appends steps g to l after `step_f_single_capture`. Until then a block that fails in every read across two or more captures reports `CRC failed` with reason `None` via `undecided`. It never carries a payload, so it cannot be exported.
