## Task 20.4: Implement downloads, JSBeeb help, and wire the app
Requirements: 11.6, 18.4, 18.5, 18.6, 18.7
Run from `/home/vamsik/TapeRescue` with Node packages already in `web/node_modules`, `.venv`, and the built decoder at `build/decoder/ScanTape`. Nothing was installed, committed or pushed. Source changes are only under `web/src/`; `web/dist` was rebuilt by `npm run build`.
### Changes
- `web/src/DownloadBar.tsx` (new): **Download report** is always enabled, including for refused sessions. **Download tape image** is `disabled` while `export.permitted` is false. The blockers are listed beside it as `Block N: <message> <code>`, with the message taken from `report.export.messages`, and the list is linked to the button with `aria-describedby`. When the image contains reconstructed blocks, clicking opens a native modal `<dialog>` (`showModal()`, falling back to the `open` attribute where `showModal` is missing, as in jsdom). The dialog lists each reconstructed block as `Block 6: Reconstructed · CRC match. CRC match is evidence, not proof of the original bytes`, with the label taken from the report. Nothing is fetched until **Continue download** is pressed. Focus moves to that button when the dialog opens. Escape or **Cancel** closes it and returns focus to the tape button. A 409 on download replaces the shown blockers with the server's and disables the button. Other errors appear in a `role="alert"` line. Fetch and save functions can be passed in as props; the defaults are `fetchReportFile` / `fetchTapeFile` from `api.ts` and `saveBlob`.
- `web/src/download.ts` (new): `saveBlob(blob, filename)` creates a `blob:` object URL, clicks a hidden `<a download>`, removes it and revokes the URL after 1 s. `safeCassetteName` applies the server's `[A-Za-z0-9_-]{1,10}` rule.
- `web/src/JsBeebHelp.tsx` (new): a plain outbound link to `https://bbc.xania.org/` (`target="_blank" rel="noopener noreferrer"`), with no iframe or embed. Steps: download the `.uef`, open JSBeeb, load the file with the emulator's local tape picker (the page states that TapeRescue does not send it to JSBeeb), type `*TAPE`, then `CHAIN "STARMAP"`. The name comes from the session's cassette name when known and defaults to `STARMAP`.
- `web/src/App.tsx` (replaces the placeholder):
  - A file input (`multiple`, WAV accept list) with a **Recover** button, enabled only for one or two files. Selecting three or more shows an alert.
  - **Try sample** calls `runSample()`.
  - Each upload is listed with its display name, "decoded" or "rejected", and its error messages. The messages come from `envelope.errors` on a 200, or from `ApiError.captureErrors` on a 422, when no envelope exists. Session-level errors (`capture_index: null`, for example `no_anchor`) are listed separately. Any other `ApiError` message (400, 404, 503) is shown as one alert.
  - One `CaptureStrip` per `report.inputs` entry, titled with the upload display name (two uploads with the same ID are joined with ` / `). Then `MergedStrip`, `BlockInspector` (with display names) and `DownloadBar`. The tape file name is `<cassette name>.uef`, taken from a valid block 0 header in the observations.
  - Selection defaults to the first merged block that is not `Intact` (`defaultBlock`), which is block 6 in the sample.
  - When a new session replaces the old one, the app sends `DELETE` for the old session and ignores any failure.
- `web/src/downloads.css` (new): styles for the buttons, blockers, dialog and its `::backdrop`, the upload row and the JSBeeb section. There are no inline `<style>` tags. Cell colours are still set through React's `style` prop, which uses the CSSOM.
- `web/src/downloads.test.tsx` (new, 3 tests), using the recorded report fixtures:
  - Damaged A alone: the tape button is disabled, the blocker reads `Block 6: <single_read message> single_read`, clicking the tape button fetches nothing, and the report downloads as `taperescue-report.json`.
  - Both captures: the dialog lists block 6 with the evidence label, focus is on **Continue download**, Cancel closes the dialog without fetching and returns focus, and confirming saves the tape blob as `STARMAP.uef`.
  - JsBeebHelp: the link `href`, `target` and `rel`; the local tape picker, `*TAPE` and `CHAIN "STARMAP"` steps; no iframe.
