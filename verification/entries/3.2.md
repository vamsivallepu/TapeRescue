## Task 3.2: Implement `taperescue/crc.py`
Requirements: 6.1, 6.2
### Changes
- `taperescue/crc.py`: table-driven `crc16_xmodem(data, init=0x0000) -> int`. Polynomial 0x1021 (`POLY`), MSB-first (no input or output reflection), final XOR 0x0000. The 256-entry table is built once at import. `init` outside `0..0xFFFF` raises `ValueError`. Passing a previous result as `init` continues the calculation.
### Commands and results
| Command | Result |
| --- | --- |
| `.venv/bin/python -c 'from taperescue.crc import crc16_xmodem as c; p=bytes((17*i+11*i*i+42)%256 for i in range(256)); v=b"123456789"; print(f"check={c(v):#06x} test_payload={c(p):#06x} len={len(p)}")'` | `check=0x31c3 test_payload=0xac93 len=256` |
| Ad hoc cross-check (inline `python -c`): 2000 random byte strings of length 0 to 299 (`random.Random(0)`), comparing against a bitwise reference loop and checking that appending the CRC high byte first gives residue 0 | `bitwise_mismatches=0 empty=0x0000` |

Both Requirement 6 vectors match: ASCII `123456789` gives `0x31C3` (6.1), and the Test_Payload `payload[i] = (17*i + 11*i*i + 42) mod 256` gives `0xAC93` (6.2). The cross-check was a one-off command line check. The formal vector tests belong to task 3.3 (`tests/test_crc.py`), which this task did not create.
