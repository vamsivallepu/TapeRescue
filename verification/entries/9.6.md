## Task 9.6: Clean-fixture UEF integration test
Requirements: 4.11, 11.4, 11.5
### Changes
- `tests/integration/test_clean_uef.py` (new). A module-scoped fixture runs the whole path once on `fixtures/starmap/clean.wav`: SHA-256 of the WAV, `decode_capture` with the patched `build/decoder/ScanTape`, `recover([capture])`, `export_decision`, `export_uef` (which also runs `verify_export`), `read_uef` on the written image, then SHA-256 of the WAV again. The module is skipped with a message naming `scripts/build_decoder.sh` when the decoder is missing, the same pattern as `tests/integration/test_fixture_decode.py`.
- Tests:
  - `test_input_wav_is_unchanged`: the WAV SHA-256 before the run equals `wav_sha256["clean.wav"]` in `reference_payloads.json`, is the same after the run, and equals the capture ID.
  - `test_eight_intact_blocks_and_export_permitted`: final block 7, blocks 0 to 7 all `Intact`, the gate permits export with no blockers and no reconstructed blocks, and the image file exists.
  - `test_uef_crcs_equal_recorded_and_reference_crcs`: the reader finds blocks 0 to 7. For each block, `header_raw`, the header CRC in the file and the data CRC in the file equal the values recorded in the clean capture's observation and the values in `reference_payloads.json`. The reference values come from the fixture encoder, so they are a source independent of the decoder. `header_crc_ok` and `data_crc_ok` are true, so both CRCs recompute from the file bytes with the reader's own bitwise CRC. Payload, filename, load and exec addresses, block length and flags also match.
  - `test_concatenated_payload_equals_reference_program`: the payloads read from the image join to 2025 bytes with SHA-256 `program_sha256` (`4ac213a0…6e3a`), and equal `result.program_payload()`.
  - `test_final_flag_only_on_block_7`: only block 7 has flag bit 7 set in the image.
