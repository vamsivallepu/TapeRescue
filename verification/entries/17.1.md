## Task 17.1: Baseline benchmark and `taperescue benchmark`
Requirements: 15.1, 15.2, 15.3, 15.4
### Changes
- `taperescue/benchmark.py` (new):
  - `run_modes(captures, names, reference_sha256)` runs three in-process modes on the same decoded captures. `best_single_capture` recovers each capture alone and keeps the one with the most `Intact` blocks, with ties going to the lowest capture ID. `intact_only_merge` uses `RecoverOptions(reconstruct=False)`. `taperescue` is full recovery. Each mode reports the recovered block count (`Intact` or `Reconstructed · CRC match` among blocks `0..final`), `complete_program` (every required block recovered and the export gate permits export), `matches_reference` (recovered program SHA-256 equals the reference `program_sha256`; `null` when no program was produced), the reconstructed block numbers, and each unrecovered block with its status and reason.
  - `quadbike_comparison(wavs)` runs only when `php` is on `PATH`, `QUADBIKE_LSBLOCKS` names `lsblocks.php`, and `QUADBIKE_BIN` names the Quadbike executable. In that case each WAV is transcribed with `[quadbike, "-t", capture.tibet, wav]`, and then `[php, "-f", lsblocks, "+r", capture.tibet]` runs, both with argument lists and `shell=False` inside a temporary directory. The block rows and the `M: Metrics|Errors|E|Blocks|N` line are parsed from the real stdout. Otherwise the result is `{"ran": false, "reason": ...}` naming every missing piece.
    - Deviation from the task wording `php lsblocks.php +r <wav>`: section 9 of the Quadbike manual gives the usage `php -f lsblocks.php [options] <CSW/TIBET/TIBETZ file>`, and `lsblocks-1.2.php` checks for the CSW magic `Compressed Square Wave`. A WAV cannot be passed directly, so a Quadbike transcription step (`quadbike -t output.tibet input.wav`, from the manual's "Using Quadbike" section) comes first. That step is why `QUADBIKE_BIN` exists.
  - `run_benchmark`, `render_markdown`, `write_results` write `results.json` and `results.md`. The JSON has `"heading": "Inputs: generated STARMAP fixtures"` as its first key. The Markdown file's first line is `# Inputs: generated STARMAP fixtures`. Neither file contains timestamps or absolute paths. The contribution is stated as "reconstruction across captures with byte provenance".
- `taperescue/cli.py`: new `benchmark [--fixtures DIR] [--out DIR] [--decoder PATH] [--timeout S]`. `--fixtures` defaults to `fixtures/starmap` in the repository and `--out` defaults to `benchmarks`. The command validates and decodes `damaged_a.wav` and `damaged_b.wav` with the patched decoder, loads `reference_payloads.json`, and runs inside `_inputs_unchanged` (exit 11 if an input changes). It writes the two result files and prints the table. It reuses the existing exit codes: 3 for a rejected capture, 5 to 8 for decoder failures, 10 for no anchor, and 1 when the output cannot be written. No existing command or exit code changed.
- `tests/test_benchmark.py` (new, minimal): Quadbike absent gives `ran: false` with a reason; `parse_lsblocks` on rows in the manual's format; with the decoder, two `benchmark` runs give byte-identical files, both headed as required, with the mode counts below.
- `verification/pending.md`: P4 stays `pending` with an empty evidence field. It now says why the comparison did not run and how to run it.
- `benchmarks/results.json`, `benchmarks/results.md`: generated by the run below.
