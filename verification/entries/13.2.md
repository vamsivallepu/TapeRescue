## Task 13.2: Write property test for order independence
Property 12: Input order does not change results. Validates Requirements 8.3, 10.6, 13.1.
### Changes
- `tests/properties/test_prop_order_independence.py` (new). It is tagged `# Feature: tape-rescue, Property 12: Input order does not change results`. All strategies are local to the file. Settings: `max_examples=300`, `derandomize=True`, `deadline=None`, `database=None`.
  - `sessions()` builds one or two captures with 64-hex capture IDs and 2–5 blocks. Non-final blocks hold 256 bytes and the final block holds 0–40 bytes, so some sessions pass the export gate. Payload bytes are expanded from a 4-byte drawn seed with SHA-256.
    - With two captures, block 0 is an intact anchor in both about 5 times in 6. The remaining sessions may have no anchor.
    - Each block of each capture gets one read drawn from a weighted mix: intact; damaged with the original recorded CRC (1–3 single-bit flips); truncated; unreadable data CRC; invalid or unreadable header CRC, with the raw block number sometimes corrupted; absent; intact with other bytes (payload conflict); header disagreement (flags or load address changed); and a different recorded CRC.
    - About 1 block in 3 is damaged in every capture, so bounded reconstruction is reached often.
    - About 1 read in 5 gets a re-read of a random kind, at a later sample offset or at the same offset, which tests tie-breaking.
    - Sometimes a duplicate capture is appended: either an exact copy, or a copy with the same capture ID and one observation dropped.
  - `permuted(caps)` draws a permutation of the capture list and of each capture's observation tuple.
  - `test_input_order_does_not_change_results` compares the generated order, a drawn permutation and the reversed order. All three must give an equal `RecoveryResult`, an equal `export_decision`, byte-identical `dumps_report(build_report(...))` text and an equal `program_payload()`. Alternatively, all three must raise `PairingRejected` with the same code and message.
  - `test_pairing_rejected_in_every_order` uses `unanchored_sessions()`: two captures where each block is intact in at most one capture. The other capture holds that block damaged, with other bytes, with an unreadable CRC, with an invalid header, or not at all. `PairingRejected("no_anchor")` must be raised for the generated, permuted and reversed orders.
  - `test_generator_reaches_interesting_cases` runs the generator over a fixed sample and requires minimum counts, so the property cannot pass on trivial sessions.
