## Task 6.3: Block builder
Requirements: 4.3, 4.4, 4.5
### Changes
- `taperescue/fixtures/block_builder.py`:
  - `TapeBlock` (frozen): filename, load/exec/next addresses, block number, flags, payload, `header_raw`, `header_crc`, `data_crc` (None for an empty block), and a `block_len` property.
  - `ByteFrame` (frozen): `value`, `role` (`sync`, `header`, `header_crc`, `payload`, `data_crc`), and `offset` within that role. For payload frames `offset` is the payload offset, which is what the damage injector (task 6.6) targets. CRC frames use offset 0 for the high byte and 1 for the low byte.
  - `encode_header(...)`: filename (1-10 printable ASCII characters, no spaces) + `0x00`, then load (4 LE), exec (4 LE), block number (2 LE), block length (2 LE), flags (1), next-file address (4 LE). Rejects out-of-range fields.
  - `build_blocks(program, filename="STARMAP", load_addr=0xFFFF0E00, exec_addr=0xFFFF8023, next_addr=0)`: 256-byte blocks except the last, numbered from 0. Flag bit 7 on the last block only. Bit 6 only for an empty block (an empty program gives one block with flags `0xC0` and no data CRC). A program that is an exact multiple of 256 bytes gets no extra empty block. Header CRC over `header_raw` and data CRC over the payload, both from `crc16_xmodem`.
  - `block_frames(block)`: tape order sync `0x2A`, header bytes, header CRC high byte first, payload, data CRC high byte first. Payload and data CRC are omitted for empty blocks.
  - Imports only `taperescue.crc`, not `taperescue.decoder_adapter`.
- `tests/test_block_builder.py`: 15 unit tests. They cover block count and sizes for a 1800-byte program (8 blocks), the final flag, exact multiples of 256, the header layout, CRC values, frame roles and offsets and CRC byte order, the empty-program block, rejection of bad filenames and out-of-range fields, and the import check. One test writes the frames of all 8 blocks into a hand-built UEF (`0x0100` chunks) and parses it with the independent `taperescue.uef.reader`. The reader's header fields, payloads, and stored CRCs equal the builder's, and the reader's own bitwise CRC confirms both CRCs.
