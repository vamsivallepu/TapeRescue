## Task 6.1: BASIC tokenizer
Requirements: 4.2
### Changes
- `taperescue/fixtures/tokenizer.py`: `tokenize(source) -> bytes`, `detokenize(program) -> str`, `normalise(source) -> str`, `TokenizeError(ValueError)`, `KEYWORDS` (keyword, token, flag byte) in ROM table order, `TOKEN_TEXT` (token to keyword, including the statement-form pseudo-variables 0xCF to 0xD3).
- Line format `0x0D, line_hi, line_lo, length, body`, where the length byte counts the whole line including the 4-byte prefix (maximum 255). The program ends with `0x0D 0xFF`. Line numbers must be 0 to 32767 and strictly ascending.
- The tokenizer follows the BASIC II ROM `MATCH` routine:
  - Keywords match in ROM table order and the first match wins. The ROM puts every keyword before any shorter keyword that is its prefix (ENDPROC before END, GET$ before GET, INKEY$ before INKEY, MODE before MOD, ERROR before ERR), so the first match is always the longest match. A test checks this for every pair of keywords.
  - Text inside string literals is not tokenized, and neither is the rest of the line after `REM` or `DATA` (flag bit 5) or after a `*` command at the start of a statement.
  - The name after `PROC` or `FN` is not tokenized (flag bit 3). Hex constants after `&` are not tokenized.
  - If a word starts with something other than a keyword, the whole word is copied as text, so `XPRINT` stays a variable name.
  - A conditional keyword (flag bit 0) that is followed by a word character is treated as a variable name, for example `ENDX`. Keywords without that flag are tokenized at the start of a name, as the ROM does: `TOTAL` becomes `TO` + `TAL`.
  - `PTR`, `PAGE`, `TIME`, `LOMEM` and `HIMEM` get +0x40 at the start of a statement (flag bit 6). The start-of-statement state is set by `:`, `THEN`, `ELSE` and `ERROR` and cleared by flag bit 1, names, numbers and punctuation, as in the ROM.
- Rejections, all raised as `TokenizeError`:
  - A number in the line-number position after GOTO, GOSUB, THEN, ELSE, RESTORE, TRACE, AUTO, DELETE, LIST or RENUMBER (flag bit 4). These are the exact places where the ROM would emit `0x8D`. A computed `GOTO X` is not rejected, because the ROM stores it without `0x8D`.
  - Keyword abbreviations (`P.`).
  - Non-printable or non-ASCII source characters, and lines whose tokenized length is over 255 bytes.
  - In `detokenize`: `0x8D`, the unused token `0xCE`, a bad framing or length byte, and bytes after the terminator.
- Source format: `<line number> <body>`. One separator space after the line number is not stored, so indentation beyond it is kept. Blank lines are ignored. `detokenize(tokenize(src)) == normalise(src)`.
- `tests/test_tokenizer.py`: 49 unit tests covering token values, framing, longest match, untokenized regions, ROM quirks, rejections, and a STARMAP-style round trip.
### Token table sources
The full BASIC II table is included (121 keyword entries plus the five pseudo-variable statement tokens). A partial table would make the tokenizer disagree with the ROM on programs that use any omitted keyword. The table was checked against two sources:
1. The BBC BASIC II ROM keyword table (`TOKENS`, with flag bytes) and token constants in the annotated BASIC II/III disassembly at https://github.com/ivop/bbc-basic (`basic.s`). That disassembly is based on J.G. Harston's source reconstruction (https://mdfs.net/Software/BBCBasic/BBC/). A one-off script parsed the `dta` lines in the BASIC II branch and compared them with `KEYWORDS`: all 121 entries were identical in order, token value and flag byte.
2. The BBC BASIC program format page at https://fileformats.org/code/program/bbc/basic/, whose table was compared there against the BASIC II ROM image. A one-off script compared its token-to-keyword pairs with `TOKEN_TEXT`: 126 entries, no mismatches.

Every value named in the task matches both sources: PRINT &F1, MODE &EB, DEF &DD, PROC &F2, END &E0, FOR &E3, NEXT &ED, GCOL &E6, MOVE &EC, DRAW &DF, PLOT &F0, VDU &EF, READ &F3, DATA &DC, REM &F4, RESTORE &F7, RND &B3, ENDPROC &E1, TO &B8, STEP &88, IF &E7, THEN &8C, ELSE &8B, COLOUR &FB, CLS &DB, LOCAL &EA, SIN &B5, COS &9B, INT &A8, AND &80, OR &84, NOT &AC, REPEAT &F5, UNTIL &FD, GOTO &E5, GOSUB &E4. No token was left out for lack of verification.

### Blockers
None. Notes:
- How BBC BASIC stores the spaces between the line number and the body is not modelled. This tokenizer drops exactly one separator space. That affects program size by at most one byte per line and does not change how the program runs.
- The property test for the round trip (Property 4) belongs to task 6.2 and was not written here.
