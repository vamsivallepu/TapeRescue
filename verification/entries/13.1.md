## Task 13.1: Implement `taperescue/engine/report.py`
Requirements: 9.13, 10.1, 10.2, 10.3, 10.4, 10.5, 10.6
### Changes
- `taperescue/engine/report.py` (new). Imports only `taperescue.models`, `taperescue.engine.gate`, `hashlib` and `json`.
  - `REPORT_SCHEMA = "taperescue.report/1"`, `ALGORITHM_VERSION = "taperescue-merge/1.0.0"`.
  - `build_report(result, decision=None)` returns a JSON-native dict (`decision` defaults to `export_decision(result)`). It follows the design's report schema. Top level: `schema`, `algorithm_version`, `candidate_cap`, `reconstruction_enabled`, `inputs` (`capture_id`, `sha256`, `observation_count`), `duplicates_merged`, `anchors`, `final_block`, `blocks`, `export`, and `recovered_payload_sha256`. The digest key is present only when `program_payload()` is not `None`, meaning every block `0..final` is recovered.
  - Each block entry holds `block_no`, `status`, `reason`, `reason_message`, `label`, `supporting_capture_ids`, and `reads`. Each read lists `capture_id`, `sample_offset`, `header_crc` and `data_crc` outcomes, `recorded_data_crc`, `expected_len`, `actual_len`, `payload_state` and `payload_sha256`. The block entry also holds block-level `recorded_data_crc` and `reconstruction` (`attempted`, `candidate_count`, `evaluated_count`, `match_count`, and `choices` with `offset`, `observed` `{capture_id: value}`, `chosen` and `supporting_capture_ids`), plus `conflict` and `payload_sha256`.
  - Design choices:
    - Intact-only `CRC failed` blocks, and any block where no search ran, report `reconstruction.attempted: false` with null counts and no choices.
    - Unrecovered blocks have `chosen: null` on every offset and `payload_sha256: null`.
    - Invalid-header reads show outcomes and lengths only. Their `recorded_data_crc` and `payload_sha256` are null.
    - Block-level `recorded_data_crc` is null when any deciding read is unreadable or the reads disagree. Per-read values stay under `reads`.
    - Payload conflicts report `conflict: {"kind": "payload", "capture_ids": [...]}`.
  - `STATUS_LABELS` gives one label per status. Reconstructed blocks get `RECONSTRUCTED_LABEL = "CRC match is evidence, not proof of the original bytes"`, which is distinct from the Intact label (Requirement 9.13).
  - `REASON_MESSAGES` is the single text table for every `UnresolvedReason` code and every export-gate code in `GATE_REASONS`. `reason_message(code)` and `block_reason_code(block)` use the gate's fallback codes `crc_failed` and `payload_conflict` when the engine left the reason unset. `export.messages` maps each blocker code to its text, so the UI does not need its own copy of the table.
  - `dumps_report` = `json.dumps(sort_keys=True, indent=2)`. `loads_report` parses the text and raises `ValueError` unless `schema` is `taperescue.report/1`.
  - No timestamps, paths, host or upload filenames, or upload order. Every list is sorted by block number, then capture ID and sample offset, then offset.
- `tests/engine/test_report.py` (new, 14 tests): identical bytes for the same input; identical bytes with capture order swapped; dumps/loads round trip and canonical text; default decision; no timestamps, paths or forbidden keys; top-level fields including a merged duplicate; the brief's unique-repair case (16/16/1, offsets 23/75/128/241, observed values, chosen value, supporting capture, recorded CRC `0xAC93`, label differs from Intact); digest present only when complete (no_match case has none and no chosen bytes); intact-only `attempted: false`; unreadable CRC and truncated read have no filled-in bytes or CRC; payload conflict object; reason table coverage; import purity (AST); real-WAV smoke test on `damaged_a.wav` + `damaged_b.wav` (skipped without the decoder).
