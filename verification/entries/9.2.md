## Task 9.2: Implement the export gate
Requirements: 11.1, 11.2
### Changes
- `taperescue/engine/gate.py`: `ExportDecision(permitted, blockers, reconstructed_blocks)` and `export_decision(result)`, a pure function that imports only `taperescue.models`. The design passes the decision alongside the result (`build_report(result, decision)`, `export_uef(result, decision, out)`), and `RecoveryResult` has no decision field, so `recover()` is unchanged and `taperescue/engine/__init__.py` was not edited.
- Export is permitted only when:
  - a final block is known (`result.final_block`, the lowest valid-header block with flag bit 7);
  - every block `0..final` has exactly one result, with status `Intact` or `Reconstructed · CRC match` and a payload;
  - each required block's valid-header reads share one identity key. The header checked is the one from the lowest-capture-ID valid-header read, which is the one the exporter writes;
  - all required blocks share filename, load address and execution address. The reference is the most common triple, with ties going to the lowest block number, so the odd block is the one blamed;
  - header `block_no` equals the position;
  - flag bit 7 is set on the final block and on no other block, and no unplaced valid-header read of the same file lies past the final block;
  - non-final blocks declare 256 bytes, the final block declares at most 256, and the payload length equals the declared length.
- Blockers are `(block_no, reason)` pairs, deduplicated and sorted by block number, then reason. The reason is the engine's `UnresolvedReason` when one is set. Otherwise it is a gate code from `GATE_REASONS` (`block_missing`, `crc_failed`, `filename_mismatch`, `address_mismatch`, `block_no_mismatch`, `unexpected_final_flag`, `final_flag_missing`, `block_len_invalid`, `payload_length_mismatch`, `header_disagreement`, `header_invalid`, `payload_missing`, `duplicate_block`, `payload_conflict`, `unresolved`).
- With no final flag, the gate adds a synthetic `(max_block_no + 1, "block_missing")` entry for the missing final block, or `(0, "block_missing")` when there are no blocks.
- `reconstructed_blocks` lists required blocks with status `Reconstructed · CRC match`, whether or not export is permitted.
- `tests/engine/test_gate.py`: 19 byte-array tests (no WAVs).

The tests cover these cases:
- Permitted: all intact; empty final block; a Reconstructed block (hand-built), which is listed in `reconstructed_blocks`; two captures whose failures are covered by the other capture's intact reads.
- Refused, each with the exact blocker tuple:
  - missing block `(2, block_missing)`;
  - single-capture CRC failure `(1, single_read)`;
  - CRC failed with no engine reason `(0, crc_failed)`;
  - no final flag `(3, block_missing)`;
  - no reads at all `(0, block_missing)`;
  - final flag on a non-final block, both through `recover` (block 1 flagged, blocks 2 and 3 follow) and hand-built: `(1, unexpected_final_flag)`;
  - final block without the flag `(3, final_flag_missing)`;
  - filename mismatch `(2, filename_mismatch)`;
  - load or exec address mismatch `(n, address_mismatch)`;
  - header block number differs from position `(2, block_no_mismatch)`;
  - 200-byte non-final block `(1, block_len_invalid)`.
- Ordering: blockers are sorted when reads arrive out of order.
- Purity: an AST import check confirms the only project import is `taperescue.models`.
