## Task 5.1: Implement `taperescue/decoder_adapter/schema.py`
Requirements: 2.2, 2.4, 2.5, 2.6, 2.7, 2.8
### Changes
- `taperescue/decoder_adapter/schema.py`:
  - `DecoderError(code, message, capture_id, detail=None)` with `code` one of `timeout`, `decoder_failed`, `invalid_output`, `no_blocks`. Attributes `code`, `message`, `capture_id`, `detail`. Task 5.2 (`run.py`) should import it from here.
  - `parse_observations(doc, expected_capture_id) -> CaptureObservations`. Every rule failure raises `DecoderError("invalid_output")` with the message `Decoder output was invalid for capture <id>: <rule detail>`. Any `ValueError` from the model constructors is converted the same way.
  - `observations_to_doc(capture) -> dict`, the inverse serialiser, so task 5.3 can test the Property 2 round trip.
  - `SCHEMA_ID = "taperescue.observations/1"`.
- `tests/decoder_adapter/test_schema.py`: 50 unit tests covering valid documents (failed complete block, intact block, truncated, empty, unreadable and invalid header CRC, block order, round trip) and each rejection rule.
### Schema rules enforced
- Top level: `schema` equals `taperescue.observations/1`; `capture_id` equals the expected ID; `blocks` is a list; `decoder` is optional and must be an object if present.
- Per block: `len(bytes.fromhex(payload)) == actual_len`; `actual_len <= expected_len`; `expected_len == header.block_len` when the header CRC is valid; a CRC object has `recorded` if and only if `outcome != "unreadable"`, with `recorded` an int in `0..0xFFFF`; a `valid` data CRC requires `actual_len == expected_len`.
- Payloads are kept at their actual length with no padding.
### Choices made where the design is ambiguous (for matching the C++ patch in task 8)
These follow the literal field names in the design's schema example.
1. **Unknown keys are rejected** at the top level, in blocks, in `header`, and in CRC objects. Allowed optional keys are `decoder` (top level) and `time_s` (block, a non-negative number, validated then discarded because the model has no field for it). The patch must not emit other keys.
2. **`data_crc` is `null` exactly when `expected_len == 0`.** Every block with `expected_len > 0` needs a `data_crc` object. A truncated block whose CRC bytes were never reached must emit `{"outcome": "unreadable"}`, not `null`.
3. **`header` with a non-valid header CRC.** A valid header CRC requires a `header` object. When the header CRC is `invalid` or `unreadable`, the patch may emit `null` or a parsed object. An object is type-checked and then dropped, because `BlockObservation.header` is `None` whenever the header CRC is not valid. `expected_len` is not compared with `block_len` in that case.
4. **Hex** must be pairs of `[0-9a-fA-F]` with no whitespace. Upper and lower case are both accepted, and the serialiser writes lowercase.
5. **Header field ranges**: `filename` is a string of at most 10 characters; `load_addr`, `exec_addr`, and `next_addr` are in `0..0xFFFFFFFF`; `block_no` and `block_len` are in `0..0xFFFF`; `flags` is in `0..0xFF`. Booleans are rejected wherever an integer is expected.
