## Task 21.1: Write the `Dockerfile` and `.dockerignore`
Requirements: 17.6, 19.3, 19.4
Run from `/home/vamsik/TapeRescue` with Docker 29.1.3 (`docker info` works without sudo). The image was built and tagged locally as `taperescue:local` and left in the local image store. Nothing was pushed, committed, or installed into `.venv`. Only `Dockerfile`, `.dockerignore` and this entry were added. `pyproject.toml` was not changed.
### Changes
- `Dockerfile` (new, 102 lines), four stages:
  - `decoder` (`debian:bookworm-slim`): installs `g++ make cmake git zlib1g-dev`, copies only `third_party/`, `patches/` and `scripts/build_decoder.sh`, then runs the build script. The script checks the vendored revision and tree id, applies the patch with `git apply`, and builds `ScanTape`. It runs offline because the vendored tree is present. The stage then checks that the usage text lists `-json <file>` (the patched option). It reads `ScanTape`'s exit 255 without using a pipe, so hadolint DL4006 does not apply.
  - `web` (`node:22-bookworm-slim`): `npm ci`, then `npm run build` (`tsc -b && vite build`). **This differs from the task text (node 20).** `web/package.json` declares `"engines": {"node": "^22.12.0 || >=24.0.0"}` because Vite 8 requires it, so Node 20 is outside the supported range. The local toolchain is Node 22.19.0.
  - `wheel` (`python:3.12-slim-bookworm`): `pip wheel --no-deps .` with `pyproject.toml`, `LICENSE`, `TapeRescue-Kiro-Brief.md` (the `readme`) and `taperescue/`.
  - `runtime` (`python:3.12-slim-bookworm`): installs `zlib1g libstdc++6` for ScanTape's dynamic links, so glibc and libstdc++ come from the same Debian release as the decoder stage. It creates system user/group `taperescue` with uid/gid 10001 and installs `taperescue-0.1.0-*.whl[server]` with the server dependencies pinned to the versions the API tests ran on: `fastapi==0.165.0`, `starlette==1.10.0`, `uvicorn==0.54.0`, `python-multipart==0.0.34`, `anyio==4.16.0`. It then copies `server/{__init__,app,sessions}.py` to `/app/server/`, `ScanTape` and `BUILD_INFO` to `/app/bin/`, `web/dist` to `/app/web/dist/`, and `clean.wav`, `damaged_a.wav` and `damaged_b.wav` to `/app/fixtures/starmap/`. The process runs as `USER 10001:10001` (numeric IDs, hadolint DL3066) with `EXPOSE 8000` and `CMD ["uvicorn", "server.app:app", "--host", "0.0.0.0", "--port", "8000"]`. Files under `/app` are owned by root and not writable by the app user.
- `.dockerignore` (new): excludes `.git`, `.gitignore`, `.venv`, `build`, `**/node_modules`, `web/dist`, `*.egg-info`, `demo-out`, `**/__pycache__`, `**/*.py[cod]`, `.pytest_cache`, `.hypothesis`, `**/*.rom`/`*.ROM`/`*.Rom`, `**/jsbeeb`, `**/jsbeeb-*` and `**/JSBeeb`. Docker's patterns are case-sensitive, so `web/src/JsBeebHelp.tsx` stays in the context. Nothing in `third_party/` matches a pattern, so the build script's tree-id check still passes.
### Findings from the code
- Server paths (`server/app.py` lines 99–107): `REPO_ROOT = Path(__file__).resolve().parents[1]`. The defaults are `build/decoder/ScanTape`, `fixtures/starmap` and `web/dist` under that root, and env vars `TAPERESCUE_DECODER`, `TAPERESCUE_FIXTURES` and `TAPERESCUE_STATIC` override them. The image sets all three explicitly: `TAPERESCUE_DECODER=/app/bin/ScanTape`, `TAPERESCUE_FIXTURES=/app/fixtures/starmap`, `TAPERESCUE_STATIC=/app/web/dist`. It also sets `PYTHONDONTWRITEBYTECODE=1` and `PYTHONUNBUFFERED=1`.
- Packaging: `[tool.setuptools.packages.find] include = ["taperescue", "taperescue.*"]`, so `server/` is not in the wheel. The Dockerfile copies it as source into `/app`, and `/app` is the working directory, so `server.app` imports from there.
- Dependencies: the `server` extra already declares `fastapi`, `uvicorn` and `python-multipart` (plus `httpx`). `anyio` and `starlette`, which `server/` imports directly, come in through FastAPI. Nothing was missing, so `pyproject.toml` is unchanged.
- Sessions use `tempfile.mkdtemp` in `/tmp`, which the non-root user can write to. In the running container, the session root was `drwx------ taperescue taperescue /tmp/taperescue-sessions-b7ljefra`.

### Notes for later tasks
- Task 21.2 (`tests/smoke/test_container.py`) can repeat the `docker export … | tar -t` scan used above. Building takes about 1–2 minutes with a cold cache, so the test should skip when Docker is unavailable.
- README (task 23.x): `docker build -t taperescue .` then `docker run --rm -p 8000:8000 taperescue`. The UI is at `http://127.0.0.1:8000/`.
- Base images use tags (`debian:bookworm-slim`, `node:22-bookworm-slim`, `python:3.12-slim-bookworm`), not digests, so rebuilds pick up Debian security updates. Pinning digests would make builds fully reproducible.
- Deployment to a public URL is still a Pending_Item. This task only built and ran the image locally.
