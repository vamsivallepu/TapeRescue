## Task 19.3: Implement `server/app.py`
Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 10.8, 17.1, 17.3, 17.4, 17.5, 19.1, 19.2
Run from `/home/vamsik/TapeRescue` with `.venv` (FastAPI 0.165.0, Starlette 1.10.0, python-multipart 0.0.34, httpx 0.28.1) and the built decoder at `build/decoder/ScanTape`. Nothing was installed, committed or pushed. Only `server/app.py`, `tests/server/test_app.py` and this entry were added.
### Changes
- `server/app.py` (new): `create_app(...)` factory plus the module-level `app` for `uvicorn server.app:app`.
  - Configuration: `TAPERESCUE_DECODER` (default `build/decoder/ScanTape`), `TAPERESCUE_FIXTURES` (default `fixtures/starmap`), `TAPERESCUE_STATIC` (default `web/dist`, mounted at `/` only if it holds `index.html`). Defaults are relative to the repository, not the working directory. The factory also takes a session parent directory, a clock, the decoder timeout (default 60 s) and the sweep interval, for tests.
  - Lifespan: creates the `SessionStore` (private 0700 root), starts a sweep task every 60 s that calls `store.sweep()` in a worker thread and drops the swept sessions' in-memory results, and on shutdown cancels the task and calls `store.close()`.
  - `POST /api/sessions`: reads the multipart form with `max_files=2`. Files in field `captures` are streamed into the session by `SessionStore.save_upload` under `capture_0.wav` / `capture_1.wav`. The user filename is display text only. A `Content-Length` over 2 × 64 MiB + 1 MiB, or a streamed body over that, returns 413. A single upload over 64 MiB becomes a `too_large` capture error.
  - `POST /api/sample`: copies `damaged_a.wav` and `damaged_b.wav` into a new session with `save_upload_sync`, then runs the same pipeline. Returns 503 if the files are missing.
  - Pipeline, run in one `anyio.to_thread.run_sync` call: decoder check (503 if missing or not executable), then for each capture `validate_capture` (wavcheck) and `decode_capture(path, decoder=..., workdir=session dir, timeout_s=60)`, then `recover`, `export_decision`, `build_report`. The report text is `dumps_report(report) + "\n"`, the same bytes the CLI writes.
  - Envelope, matching `SessionEnvelope` in `web/src/api.ts`: `session_id`, `captures` (`index`, `display_name`, `capture_id`, which is `null` for a wavcheck or size rejection, and `status` `"ok"`/`"error"`), `errors` (`capture_index`, `display_name`, `code`, `message`), `report`, `observations` (keyed by capture ID; each block is the `observations_to_doc` shape plus `block_no`, which is `null` for an invalid header), and `export` (`permitted`, `blockers` as `[block_no, code]`, `reconstructed_blocks`).
  - Status rules: 200 when at least one capture decoded. A session with one rejected and one valid capture returns the valid capture's single-capture report, with the rejection in `errors`. 422 `{"errors": [...]}` when no capture decoded, or for `no_anchor` (`capture_index: null`). The session is deleted on 422 because there is nothing to show or download. 400 `{"detail": "Upload one or two WAV captures"}` for zero files, more than two, or non-file values in `captures`. Other malformed multipart bodies get a different 400 message. 404 `{"detail": "Session not found or expired"}` for unknown, expired or malformed IDs.
  - `GET /api/sessions/{sid}` returns the stored envelope. `GET .../report.json` returns the report with `Content-Disposition: attachment; filename="taperescue-report.json"`, including for refused sessions (Requirement 10.8). `GET .../tape.uef` returns 409 `{"detail", "blockers", "messages"}` when the gate refuses. Otherwise it runs `export_uef` into `<session>/tape.uef`, which verifies the file with the independent reader, and returns the bytes with `Content-Disposition: attachment; filename="<cassette name>.uef"`. The name comes from block 0's valid header and must match `[A-Za-z0-9_-]{1,10}`, otherwise it is `tape`. Verification failure returns 500 `Exported image failed verification`. `DELETE` returns 204, or 404 if the session does not exist. Every lookup goes through `store.get`, which updates `last_access`.
  - A pure ASGI middleware adds `Content-Security-Policy: default-src 'self'`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer` to every response, and `Cache-Control: no-store` to `/api/` responses. There is no CORS. OpenAPI and docs routes are disabled. The only process that sees a capture is the local decoder subprocess (argument list, `shell=False`, inside `decode_capture`).
- `tests/server/test_app.py` (new, 12 tests; 5 need the decoder and are skipped with a message when it is missing): 400 for 0 and 3 files; 422 with `capture_index` 0 for a 48 kHz stereo WAV and for non-WAV bytes, using a filename containing `../../etc/`, with no session or files left behind; 404 for unknown and malformed IDs on all four session routes; CSP, nosniff and no-store headers on API and static responses; 503 with a missing decoder. With the decoder: the sample reconstructs block 6 and the downloaded `tape.uef`, read with `read_uef`, equals the reference program and `recovered_payload_sha256`; `report.json` equals `dumps_report(envelope.report) + "\n"`; DELETE removes the session; a single capture gives a 409 with `[[6, "single_read"]]` while `report.json` still downloads; one valid capture plus one 8-bit capture gives 200 with the error on index 1; a silent WAV gives 422 `no_blocks`; the sweep with an injected clock keeps a session touched within 60 minutes and removes it, including its directory, 60 minutes after the last request.

### Notes for later tasks
- Tasks 20.x (UI): a 422 deletes the session, so the UI shows `errors` from `ApiError.captureErrors` and has no session to fetch. A 200 can carry `errors` for one rejected capture next to a report for the other.
- Task 19.4 (API tests) can extend `tests/server/test_app.py`. `no_anchor` (422, `capture_index: null`) is implemented but not tested yet, because it needs two decodable captures of different programs.
- Starlette spools multipart files to an anonymous `SpooledTemporaryFile` (memory up to 1 MiB, then the system temp dir) before `save_upload` copies them into the session and enforces 64 MiB per capture. The whole request body is capped at 2 × 64 MiB + 1 MiB while it streams.
