## Task 15: Write the byte-array acceptance tests
Requirements: 8.5, 9.13, 12.1, 12.2, 12.3, 12.4, 12.5, 12.6
### Changes
- `tests/engine/test_acceptance.py` (new, 11 tests). No engine code was changed.
  - Every case calls `recover()` on full `CaptureObservations` and asserts on the report JSON as a user downloads it: `loads_report(dumps_report(build_report(result)))`. Each case also checks that reversing the capture order gives byte-identical report text.
  - Session for the reconstruction and evidence cases: captures A (`"a"*64`) and B (`"b"*64`). Block 0 is intact and equal in both and is the anchor. Block 1 is the block under test. Block 2 is final and intact in both.
  - The data CRC outcome of each read is computed from its own bytes (`valid` only when the CRC of the observed payload equals the recorded CRC). "Both reads fail" therefore follows from the fixture bytes. Both reads record `0xAC93` in every reconstruction case.
  - Test_Payload: `payload[i] = (17*i + 11*i*i + 42) % 256`, 256 bytes.
  - `assert_no_filled_in` checks every unrecovered block. The block's `payload_sha256` is null and `supporting_capture_ids` is empty. Every choice has `chosen: null` and no supporting captures. Each read's `payload_sha256` is the digest of the bytes actually read, and its `actual_len` is the observed length, so nothing is padded. Every `recorded_data_crc` anywhere in the report is null or a value recorded in the inputs, so no CRC is computed and substituted. `recovered_payload_sha256` is absent, export is refused, and the block appears in `export.blockers`.
